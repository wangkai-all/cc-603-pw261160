# 水质事件时间线（本地演示）

传感器报数与换水工单分轨；指标从超限持续到「连续恢复」被确认才结束，短间隔抖动不拆段；
补录缺失观测后重新计算，合并段的时长按首尾重算；治理前后对照按确认时点归并，
仍未恢复的样本单列，不进入任何一侧均值。

只依赖 Node.js 内置模块（要求 Node ≥ 20，本机验证于 v24）。

## 启动

```bash
PORT=3000 node server.js
# 打开 http://127.0.0.1:3000
```

服务只绑定 `127.0.0.1`。`PORT` 未设置时默认 3000。

## 页面操作

业务结果区带 `data-evidence-result` 属性，每次操作后其 `data-evidence-version` 自增，
方便核对操作前后内容是否变化。

- **生成水质事件**：重置为本地造数（`lib/dataset.js`）并重新分段，清空补录记录。
- **补一段缺失观测**：对当前第一个「两侧都超限」的缺测区间自动补录 5 分钟一条的 COD 观测；
  补录后若两段接上则合并为一段，时长按合并后的超限起点与确认时点重算。
- **对照恢复时长**：按治理时点（输入框中的 ISO 时间）和所选归并口径，把已确认事件分到
  治理前 / 治理后；未恢复样本固定单列。口径可选「按恢复确认时点」（默认）或「按首个恢复观测」。

## 规则参数（`lib/events.js`）

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| 阈值 | COD 50、氨氮 5、浊度 20 | 严格大于阈值即超限 |
| 迟滞比例 | 10% | 回落到阈值 90% 以下才算恢复观测 |
| 连续恢复时长 | 30 分钟 | 恢复观测连续覆盖 30 分钟才确认封口 |
| 最大采样间隔 | 15 分钟 | 相邻观测超过它视为缺测 |

事件字段：`startedAt`（超限起点）、`recoveredAt`（首个恢复观测）、`confirmedAt`（恢复确认时点）、
`durationMinutes`（起点到确认时点）、`recoverySpanMinutes`（起点到首个恢复观测）。
确认时点随事件与对照结果一并返回给分析端。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 当前观测、事件、未恢复样本、缺口、默认对照 |
| POST | `/api/events/generate` | 重置数据并计算；可带 `splitAt` / `windowMode` 控制返回的对照口径 |
| POST | `/api/impute` | `{ candidate?, rows? , metric?, splitAt?, windowMode? }`；不传 `rows` 时自动补缺口 |
| POST | `/api/compare` | `{ splitAt, windowMode: "confirmed" \| "observed" }` |
